# ペルソナ設計書

## 1. 概要

IPOttoは個人投資家（自分自身）専用のツールである。本ペルソナ設計書では、「開発者としての自分」と「利用者としての自分」を分離し、利用者視点での目標・課題・行動パターンを構造化する。これにより、機能の優先順位判断やスコープ肥大化の防止に活用する。

### 1.1 ペルソナの活用方針

- 新機能の追加検討時に「このペルソナは本当にこの機能を必要としているか？」を判断基準とする
- UIの複雑さとのトレードオフが生じた場合、ペルソナの行動パターン・利用環境を基準に判断する
- Phase 2以降のスコープ判断時に、ペルソナの目標に合致するかを基準とする

## 3. ペルソナ詳細

---

### PRS-001: 中村 翔太 {#prs-001}

#### 3.1 プロフィール

| 項目 | 内容 |
|---|---|
| **名前** | 中村 翔太（なかむら しょうた） |
| **年齢** | 30代 |
| **職業・役職** | ソフトウェアエンジニア |
| **テクノロジーリテラシー** | 高。日常的にターミナル操作・クラウドサービスを利用。GCP、Docker、Terraform等のインフラ技術にも精通 |
| **タグライン** | 「IPO投資を始めたいが手作業を自動化して本業に集中したいエンジニア」 |

#### 3.2 代表的な引用（Quote）

> 「IPOは当選すればローリスクで利益が出るらしいけど、毎回証券会社にログインして申し込むのは面倒すぎる。仕組みを作って放っておけるようにしたい。」

#### 3.3 背景・コンテキスト

ソフトウェアエンジニアとして本業で忙しく、投資に大きな時間を割く余裕はない。IPO投資はローリスクな副収入として魅力を感じているが、まだ始めていない。証券口座（楽天証券）は保有している。手作業での繰り返し操作を嫌い、自動化できるものは自動化したいという志向が強い。

**利用環境:**

| 項目 | 内容 |
|---|---|
| **主要デバイス** | PC（macOS）とスマートフォン（iPhone）を同程度に利用 |
| **利用場所** | 自宅（帰宅後にPCでダッシュボード確認）、外出先（スマホで通知確認） |
| **利用時間帯** | 主に夜間（帰宅後）。日中は通知を受け取る程度 |
| **想定利用頻度** | ダッシュボード確認: 週1〜2回。通知確認: 都度。設定変更: 月1回程度 |

#### 3.4 目標（Goals）

**主要目標（End Goals）:**

1. IPO抽選の申し込みを自動化し、申し込み漏れをゼロにする
2. 当選/落選の結果を自動で把握し、対応が必要な場合のみ通知で知る
3. 全銘柄の申し込み状況・結果をダッシュボードで一目で把握できる

**体験目標（Experience Goals）:**

1. 基本的には「放置」でき、必要なときだけ確認すれば済む状態を実現する
2. 問題が起きたとき（自動操作の失敗等）は即座に気づけて安心できる

**人生目標（Life Goals）:**

1. 本業のソフトウェア開発に集中しつつ、効率的に資産を形成したい
2. 繰り返しの手作業を仕組みで解決し、自分の時間を最大化したい

#### 3.5 ペインポイント・フラストレーション

| # | ペインポイント | 深刻度 | 現在の対処法 |
|---|---|---|---|
| 1 | IPO銘柄のスケジュール管理が煩雑。ブックビルディング期間や抽選日を手動で追いかける必要がある | 高 | まだ始めていないが、手動管理が億劫で着手できていない |
| 2 | 証券会社のWebサイトに毎回ログインして申し込み操作をする手間 | 高 | （未着手の主因。この面倒さが参入障壁になっている） |
| 3 | 複数IPO銘柄が同時期にある場合、どれに申し込んだか把握しきれない | 中 | （将来的に複数証券会社に拡張した場合に顕在化する課題） |
| 4 | 自社がIPOする可能性がある場合のインサイダー規制への対応が不安 | 中 | 手動で注意する以外に方法がない |

#### 3.6 行動パターン

**典型的なワークフロー（IPOtto利用時の想定）:**

1. 【自動】システムがIPO情報を取得し、ダッシュボードを更新する
2. 【自動】ブックビルディング期間中に自動申し込みが実行される
3. 【通知】申し込み完了の通知を受け取り、スマホで内容を軽く確認する
4. 【自動】抽選結果発表日に結果が自動取得される
5. 【通知】当選した場合のみ通知が届く。ダッシュボードで詳細を確認し、次のアクションを判断する
6. 【週次】週末に帰宅後、PCでダッシュボードを開いて全体の状況を俯瞰する

**意思決定の傾向:**

- 「設定して放置」できる仕組みを好む。毎回判断が必要なフローは避けたい
- 問題が起きたときのデバッグ情報（操作ログ）は詳細に残してほしい
- 技術的な設定（Webhook URL、cron式等）には抵抗がなく、GUIよりも正確に設定できることを重視する

#### 3.7 シナリオ

##### シナリオ1: 初期セットアップ後、最初のIPO申し込みが自動実行される

翔太はIPOttoをセットアップし、楽天証券の認証情報を登録した。除外リストに自社の社名を登録し、Slackの通知チャネルを設定した。数日後、新しいIPO銘柄のブックビルディング期間が始まると、システムが自動で申し込みを実行。Slackに「○○株式会社のIPO抽選に申し込みました」と通知が届く。翔太はスマホで通知を確認し、「ちゃんと動いてるな」と安心して仕事に戻る。

##### シナリオ2: 自動操作が失敗してアラートが届く

ある朝、Slackに「楽天証券へのログインに失敗しました（3回リトライ後）」というエラー通知が届く。翔太は帰宅後にPCでダッシュボードの操作ログを確認し、楽天証券のサイトUIが変更されたことが原因と判明。エラー詳細とスクリーンショットがログに残っているため、アダプターのセレクタ設定を修正して対応する。

##### シナリオ3: 当選通知を受け取る

抽選結果発表日の夜、Slackに「○○株式会社のIPO抽選に当選しました」と通知が届く。翔太はダッシュボードで当選銘柄の詳細（公募価格、上場予定日等）を確認する。Phase 1では購入意思表示は手動で行うため、通知内のリンクから楽天証券のサイトに遷移して手続きを進める。

#### 3.8 受容基準

- [ ] セットアップ完了後、日常的にシステムを意識せずIPO申し込みが自動実行される
- [ ] 申し込み漏れが発生しない（除外リスト以外の全銘柄に申し込まれる）
- [ ] 問題発生時に5分以内に通知を受け取れる
- [ ] 週次でダッシュボードを確認するだけで全体の進捗を把握できる
- [ ] 除外リストに登録した銘柄には絶対に申し込まれない（インサイダー規制対応）
- [ ] PCでもスマホでもダッシュボードが快適に閲覧できる

## 5. アンチペルソナ（対象外ユーザー）

### NPRS-001: 田中 雄一 {#nprs-001}

| 項目 | 内容 |
|---|---|
| **概要** | 専業デイトレーダー。日中は相場に張り付き、チャート分析と短期売買で利益を追求している。複数の証券会社口座を使い分け、注文の瞬時の執行速度や高度な注文条件設定（逆指値、OCO等）を重視する |
| **対象外とする理由** | IPOttoは「放置型」の自動化ツールであり、リアルタイムの相場判断や短期売買のための機能は提供しない。デイトレーダーが求める板情報表示、約定速度の最適化、テクニカル分析機能はスコープ外（[要件定義書 2.2 対象外](../01-requirements/requirements-specification.md)参照） |
| **境界線** | Primaryペルソナは「設定して放置」する自動化を志向し、市場に張り付かない。アンチペルソナはリアルタイムの判断介入と高頻度の操作を志向する |
