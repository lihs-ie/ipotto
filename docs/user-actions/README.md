# ユーザーアクション書

本ディレクトリは、開発者だけでは決められない情報・ユーザー（プロダクトオーナーや実利用者）からの提供が必要な情報を整理するための場所。

## 1. 目的

`docs/01`〜`docs/13` は **設計成果物** が中心であり、設計者・開発者の意思決定で完結する内容を扱う。一方で、以下のような情報は外部のユーザー協力なしには確定できない:

- 証券会社サイトの実際の DOM 構造・URL パターン（実口座でないと確認不能）
- 各証券会社の利用規約上の制約（自動操作の可否、レート制限）
- 通知配信先の実情報（LINE Notify トークン、SendGrid API キー等）
- 運用上の意思決定（リリースタイミング、許可ユーザー一覧）

このディレクトリに置くドキュメントは「ユーザーが回答することで設計・実装を前進させるための質問書」として機能する。

## 2. ファイル命名規則

| パターン | 用途 | 例 |
|---|---|---|
| `<topic>-information-request.md` | 情報収集を依頼する質問書 | `nomura-broker-information-request.md` |
| `<topic>-decision-request.md` | 設計上の意思決定を依頼する書面 | `notification-channel-priority-decision-request.md` |
| `<topic>-credential-request.md` | 本番環境用の credential 提供を依頼する書面 | `production-secrets-credential-request.md` |

## 3. ドキュメント構成テンプレート

各ユーザーアクション書は以下の節を備える:

1. **概要** — 何の目的でこの情報が必要か
2. **回答期限の目安** — いつまでに回答が欲しいか
3. **回答方法** — 本ファイル内の追記 / 別ファイル添付 / 口頭ヒアリング 等
4. **質問項目** — チェックボックス `- [ ]` 形式。各項目に「目的」「期待する成果物」「想定回答例」を併記
5. **回答記入欄** — ユーザーが回答を書き込むセクション
6. **後続タスク** — 回答後に発生する開発タスクへのリンク

## 4. 進捗管理

各ファイルの冒頭 frontmatter に `status` フィールドを置き、以下のいずれかで更新する:

- `draft` — 質問書作成中
- `awaiting-user` — ユーザー回答待ち
- `in-review` — 回答内容を開発者がレビュー中
- `complete` — 回答完了。後続タスクに引き継ぎ済み
- `obsolete` — 不要になった（理由を文中に明記）
